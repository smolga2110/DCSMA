# Модуль 6. Практическая работа 3

Авторизация и каталог пользователей

## Цель

Реализовать вход по логину и паролю, сохранение токена и переход к списку и деталям пользователей.

## Реализация

KtorAuthRepository выполняет POST /auth/login в DummyJSON и сохраняет accessToken в Preferences DataStore. После входа Bearer-токен добавляется к GET /users и GET /users/{id}. Login проверяет заполнение полей. AuthViewModel управляет состояниями загрузки, данных и ошибки; выход удаляет токен и возвращает экран входа.

## Запуск

Требования: JDK 21, Android Studio, Android SDK Platform 35 и Build Tools 35. Откройте **эту папку** как отдельный проект Android Studio, дождитесь синхронизации и запустите конфигурацию app. Минимальная версия устройства — Android 8.0 (API 26). SDK задаётся через Android Studio, `ANDROID_HOME` или локальный `local.properties`.

Сборка из терминала: `./gradlew :app:assembleDebug` (Windows: `.\gradlew.bat :app:assembleDebug`). Готовый APK лежит в `apk/`; установка: `adb install -r apk/m6t03-debug.apk`.

На Windows при пути с кириллицей используйте `.\verify.ps1` (сборка) или `.\verify.ps1 run` (JVM). Сценарий обходит проблему путей Gradle test worker, размещая сборку в `%TEMP%/MobilePracticeBuild`. Произвольные задачи можно передать аргументами: `.\verify.ps1 TASK`. Путь можно переопределить переменной `PRACTICE_BUILD_DIR` на каталог с ASCII-именем. Для Android вместо TASK укажите `:app:testDebugUnitTest`, если в проекте есть тесты.

## Проверка

Учётная запись emilys успешно авторизована, после чего показан список с аватарами, именами, username и email. Использованы тестовые данные публичного сервиса. В текущем API поле называется accessToken. Маршруты /users публичны у поставщика, но клиент отправляет заголовок Authorization согласно заданию.

Используется DummyJSON. Публичная учебная учётная запись: `emilys` / `emilyspass`. Проверьте неверный пароль, вход, список, детали и выход.
