# Подготовка к защите практических работ

Памятка относится к коду в этом комплекте. Формулировки ниже — опора для объяснения, а не текст, который следует выучить без понимания. Перед сдачей самостоятельно запустите работы и найдите упомянутые методы. Не приписывайте проверкам то, что фактически не проверялось.

## Как отвечать о любой работе

Стройте объяснение в одном порядке: **задача → действие пользователя → путь данных → результат → обработка ошибки → вывод**. Например: «Пользователь вводит запрос. Предыдущая корутина отменяется, новая ждёт 500 мс, читает JSON и фильтрует записи. Состояние обновляется, Compose показывает список. Это сокращает количество поисков при быстром вводе».

Умейте показать три места: обработчик действия на экране, код основной операции и обновление состояния. Самое полезное упражнение — проследить одно нажатие от кнопки до результата, а затем объяснить, что произойдёт при повторном нажатии, повороте экрана и ошибке.

В комплекте 25 отдельных проектов: 21 Android-приложение, две консольные программы и два сервера. Каждый открывается из своей папки задания. APK — уже собранное приложение; исходный код нужен для объяснения реализации и повторной сборки. Gradle Wrapper запускает зафиксированную версию Gradle; при первом запуске скачивает её и зависимости.

## Общие вопросы по Kotlin и Android

**Что такое корутина?** Приостанавливаемая вычислительная задача. Корутина не равна отдельному потоку: множество корутин могут использовать один поток. Приостановка позволяет освободить поток на время ожидания.

**Чем suspend отличается от запуска в фоне?** `suspend` разрешает приостанавливать выполнение, но сам по себе не переносит код с главного потока. Контекст выбирается областью и диспетчером. Тяжёлое вычисление внутри suspend-функции всё равно может блокировать UI.

**launch, async, withContext?** `launch` возвращает `Job` для управления задачей; `async` возвращает `Deferred<T>`, результат получают через `await`; `withContext` выполняет блок в указанном контексте и возвращает результат. Один `withContext` не создаёт параллельное выполнение следующей строки: вызывающая корутина ждёт его завершения.

**delay и Thread.sleep?** `delay` приостанавливает корутину и поддерживает отмену; `Thread.sleep` блокирует поток.

**Какие диспетчеры нужны?** `Main` — взаимодействие с UI, `IO` — блокирующее чтение файлов и подобные операции, `Default` — вычислительная нагрузка. Переключение контекста не заменяет защиту общих изменяемых данных.

**Что такое структурированная конкурентность?** Дочерние задачи привязаны к области жизни родителя. Родитель ожидает их завершения, а отмена родителя распространяется на детей. В обычной области ошибка ребёнка может отменить остальных; `supervisorScope` позволяет изолировать сбои детей, но ошибки всё равно нужно обрабатывать.

**Почему нельзя поглощать CancellationException?** Это сигнал отмены. Если обработать его как обычную ошибку и продолжить работу, отменённая задача может выполнять ненужные действия. В наших операциях такой сигнал передаётся дальше; длительные циклы проверяют `ensureActive`.

**Что делает ViewModel?** Хранит состояние экрана и связанную логику независимо от пересоздания Activity при смене конфигурации. Она не гарантирует сохранение после завершения процесса: для этого нужны постоянное хранилище или специальные средства сохранения состояния.

**Что такое рекомпозиция?** Повторное выполнение затронутых Compose-функций при изменении наблюдаемого состояния. Поэтому сетевой запрос или запись файла нельзя безусловно запускать прямо в теле Composable при каждом его выполнении.

**remember и rememberCoroutineScope?** `remember` сохраняет значение между рекомпозициями, пока соответствующий участок остаётся в композиции. `rememberCoroutineScope` даёт область, отменяемую при выходе из композиции. Это не постоянное хранилище после перезапуска приложения.

**Как состояние попадает на экран?** ViewModel или сервис публикует состояние; UI подписывается на него и отображает актуальное значение. `collectAsStateWithLifecycle` учитывает жизненный цикл, чтобы не собирать поток, когда экран не находится в нужном состоянии.

## Модуль 4

### 1. Параллельная загрузка

- Покажите обычный запуск и запуск с `--fail`.
- Главный вопрос: почему общее время около 2,5 с, а не 5,5 с? Ожидания 1,8, 1,2 и 2,5 с идут одновременно; время определяется самой долгой задачей плюс накладные расходы.
- Почему нужны `supervisorScope` и `Result`? Первый изолирует дочерние задачи, второй позволяет представить успех или ошибку каждого источника и вывести оставшиеся результаты.
- Не называйте учебные задержки реальными HTTP-запросами.

### 2. Поиск дубликатов JSON

- Покажите каталог `samples`, совпадение `a.json` и `nested/copy.json`, затем очень короткий таймаут.
- Почему SHA-256? Сравнивается содержимое, а не имя файла. Разные имена могут иметь одинаковые байты. Хеширование здесь — не шифрование.
- Зачем блоки по 64 КиБ? В памяти не хранится файл целиком. Зачем `Semaphore(4)`? Ограничивается число одновременно открытых и обрабатываемых файлов.
- Таймаут отменяет дочерние операции; проверка отмены в цикле помогает быстро завершить чтение. Само перечисление найденных путей всё же занимает память пропорционально числу файлов.
- Коллизии хеша теоретически возможны. Для абсолютной проверки после совпадения хеша можно дополнительно сравнить байты; в задании используется хеш как критерий.

### 3. Поиск с задержкой ввода

- Быстро введите и измените запрос, затем дождитесь списка.
- Debounce означает запуск после паузы во вводе, а не периодический запуск через равные интервалы. В реализации отменяется предыдущий `Job`, новый ждёт 500 мс.
- Почему отмена важна? Чтобы прежний запрос не продолжал работу и не подменял результат нового. Локальный учебный JSON содержит 100 записей; это не живой поиск по GitHub API.

### 4. Социальная лента

- Покажите загрузку карточек и переключатель сбоев.
- Для каждого поста независимо загружаются аватар и комментарии. У карточки есть состояния Loading, Ready и Error. Ошибка одного поста не должна прятать остальные.
- При обновлении отменяется предыдущая общая задача с дочерними загрузками. Данные и задержки учебные; цветной аватар не является скачанной фотографией.

### 5. Foreground-сервис секундомера

- Нажмите «Старт», сверните приложение, покажите уведомление, вернитесь и остановите счётчик.
- Foreground-сервис выполняет заметную пользователю работу с уведомлением. **Service сам по себе не создаёт рабочий поток**: его callbacks обычно вызываются в главном потоке, поэтому для ожидания и работы нужны соответствующие корутины/контексты.
- Почему `elapsedRealtime`, а не увеличение переменной после каждого delay? Измеряются реально прошедшие монотонные интервалы; задержки планировщика не накапливают ошибку счётчика.
- Что происходит при повторном старте? Второй цикл не создаётся. Остановка отменяет работу и удаляет foreground-уведомление.

### 6. Обычный сервис таймера

- Введите 3 секунды, оставьте приложение открытым и дождитесь завершения.
- Сервис получает параметр через Intent, ждёт, уведомляет и вызывает `stopSelf`. При повторном запуске прежнее ожидание отменяется.
- Чем отличается от предыдущей работы? Это обычный background-сервис. Он подчиняется ограничениям фонового выполнения Android и не гарантирует длительную работу после ухода приложения в фон. Для точного длительного будильника нужен другой механизм. Такое ограничение прямо указано в интерфейсе и отчёте.

### 7. Bound-сервис

- Подключитесь, покажите меняющееся число, отключитесь.
- `bindService` устанавливает связь; через `ServiceConnection` приходит Binder. Локальный Binder позволяет получить сервис и подписаться на поток его значений.
- Объясните отличие запуска сервиса от привязки клиента. При завершении работы экрана подписку и привязку нужно освободить, иначе они переживут необходимую область жизни.

### 8. Цепочка WorkManager

- Выберите фотографию и покажите последовательные этапы: сжатие → водяной знак → имитация отправки.
- Почему WorkManager? Для отложенной устойчивой работы с зависимостями, повторными попытками и состояниями. Это не средство запуска строго в заданную секунду.
- `then` задаёт зависимость; данные одного Worker передаются следующему через `Data`. При ошибке предшественника зависимые этапы не продолжают успешную цепочку.
- Изображение обрабатывается реально, загрузка в облако имитируется; демонстрационный URL не подтверждает наличие облачного файла.

### 9. Параллельные Workers

- Запустите сбор и покажите три результата и среднюю температуру 4 °C.
- Три независимых Worker выполняются параллельно; финальный зависит от всех. `ArrayCreatingInputMerger` объединяет одинаковые ключи в массивы, а не теряет значения при объединении.
- Формула: `(21 − 2 − 7) / 3 = 4`. Погода учебная, не текущий прогноз.

### 10. Геолокация и адрес

- Покажите разрешения, получение координат и адреса. В эмуляторе предварительно задайте координаты.
- Fused Location Provider получает положение, Geocoder преобразует координаты в адрес. Это разные операции: координаты могут быть доступны, а адрес — нет.
- Предусмотрены отказ в разрешении, ограничение ожидания 20 с и отсутствие результата. Полученные координаты сохраняются на экране даже при неудаче геокодирования.

### 11. AlarmManager

- Разрешите уведомления и точные будильники, включите напоминание, покажите ближайшие 20:00, затем отключите.
- Почему AlarmManager? Задача привязана к определённому времени. WorkManager для точной секунды не предназначен.
- Зачем PendingIntent? Система получает описание действия, которое сможет выполнить позднее. Receiver обрабатывает событие и назначает следующее.
- Учитываются перезагрузка, смена часового пояса и времени. Часовой пояс важен для «20:00 по местному времени».

### 12. Cold Flow

- Запросите факт, дождитесь ответа, поверните экран.
- Холодный Flow начинает выполнение при сборе; само создание Flow не запускает получение результата. Новый сбор может повторить работу.
- Результат помещается в состояние ViewModel, поэтому поворот не обязан запрашивать новый факт. Не путайте поворот с уничтожением процесса.

### 13. StateFlow

- Покажите обновление через 5 секунд и ручное обновление, объясните стрелку.
- StateFlow — горячий поток состояния с текущим значением; новый подписчик получает последнее значение. В отличие от холодного Flow, подписчик не обязательно запускает вычисление заново.
- Цвет и направление стрелки определяются сравнением нового значения с предыдущим. Курс случайный учебный, не банковская котировка.

### 14. Компас

- Покажите диск, стрелку и азимут. На физическом устройстве проверьте поворот и переход через север.
- Данные rotation vector преобразуются в матрицу ориентации с учётом положения экрана. Азимут нормализуется в диапазон `[0, 360)`.
- Почему нельзя просто анимировать 359 → 1? Получится почти полный оборот в обратную сторону. Используется минимальная угловая разница, здесь +2°.
- Подписка включается при возобновлении экрана и снимается при паузе. На эмуляторе проверено отображение, физическая точность не измерялась.

## Модуль 5

### 1. Файловый дневник

- Создайте запись, откройте, измените, удалите и перезапустите приложение.
- Почему приватные файлы? Записи принадлежат этому приложению и не должны требовать общего доступа к хранилищу.
- `AtomicFile` помогает избежать повреждённой записи при незавершённой перезаписи, `Mutex` последовательно выполняет конфликтующие операции. Они решают разные задачи.
- Каталог сканируется при инициализации; после CRUD изменяется список состояния. CRUD — Create, Read, Update, Delete.

### 2. Камера и приватная галерея

- Сделайте и подтвердите снимок, покажите его в сетке.
- FileProvider предоставляет `content://` URI с ограниченным доступом для камеры. Передавать другой программе обычный файловый путь недостаточно и небезопасно.
- `TakePicture` записывает полноразмерное изображение по подготовленному URI. При отмене пустой файл удаляется.
- Файлы в каталоге приложения отличаются от общедоступной галереи: их не следует считать общими фотографиями, сохраняющимися независимо от удаления приложения.

### 3. MediaStore

- Экспортируйте фото и покажите сообщение об успехе, затем найдите изображение в системной медиатеке.
- MediaStore — системный интерфейс к общим медиа. Создаётся запись, её URI используется для записи потока байтов.
- На Android 10+ `IS_PENDING` скрывает незавершённый объект от других приложений до окончания записи. При ошибке незавершённая запись удаляется.
- Чем отличается от SAF? В этой работе экспорт управляется через MediaStore; в фотокаталоге модуля 6 пользователь сам выбирает документ/место через системный диалог SAF.

### 4. Room и DataStore

- Покажите начальные три задачи, создание и редактирование, завершение, подсветку, удаление и сохранение после перезапуска.
- Room — слой над SQLite. Entity описывает таблицу, DAO — операции с ней, Database связывает сущности и доступ.
- Поток из DAO обновляет UI при изменении таблицы. Repository скрывает конкретное хранилище, ViewModel готовит состояние экрана.
- Для чего транзакция импорта? Вставка начальных задач и запись признака импорта должны завершиться вместе. Иначе возможны частично импортированные данные или повторная вставка.
- Почему недостаточно проверки «таблица пуста»? Пользователь может удалить все задачи; это не повод импортировать их заново. Нужен отдельный признак.
- DataStore используется для небольших настроек, Room — для структурированных задач и запросов. Одно не заменяет другое во всех случаях.
- Найдите в коде `TodoDatabase.kt`, `RoomTaskRepository.kt`, `TodoPreferences.kt`, `TodoViewModel.kt`.

## Модуль 6

### 1. Retrofit и фотокаталог

- Откройте список, детали фото и сохраните фотографию в Downloads.
- Retrofit описывает HTTP API интерфейсом; DTO соответствует ответу сервера, доменная модель — потребностям приложения. Репозиторий преобразует одно в другое.
- Coil отвечает за показ и загрузку изображений в UI. Сохранение файла — отдельная операция через ContentResolver и URI, предоставленный SAF.
- Умейте показать состояния загрузки, успеха и ошибки, объяснить необходимость интернета.

### 2. Ktor Client и премии

- Выберите 2023 год, категорию, откройте премию и информацию о лауреате.
- Название категории в UI преобразуется в код API; данные ответа преобразуются в Prize и Laureate.
- Зачем отдельный запрос лауреата? Краткая запись в списке не содержит всех подробностей. Не все записи описывают физическое лицо: возможны организации.
- Схема JSON внешнего API может быть неоднородной; отсутствующее поле нужно обработать. Фотографии, которых нет в ответе, не выдаются за полученные данные.

### 3. Авторизация DummyJSON

- Покажите неверный пароль, затем вход `emilys` / `emilyspass`, список, детали и выход.
- В ответе используется поле `accessToken`; оно сохраняется в DataStore и отправляется как `Authorization: Bearer ...`.
- 401 означает отсутствие приемлемой аутентификации; это не то же самое, что ошибка сети. Токен может истечь.
- Важная особенность именно этого сервиса: `/users` публичен. Отправка заголовка реализована, но публичность маршрута не доказывает серверную защиту. Настоящая проверка доступа показана в собственном Ktor-сервере.
- DataStore само по себе не является шифрованным сейфом. В промышленном приложении отдельно проектируют защиту и срок жизни чувствительных данных.

### 4. Ktor-сервер в памяти

- Запустите сервер, откройте `/docs`, покажите запрос без токена, вход и запрос с токеном. Данные сбрасываются при перезапуске.
- Путь запроса: route → service → repository → ответ. Разделение позволяет заменить способ хранения.
- JWT состоит из заголовка, полезной нагрузки и подписи. Подпись позволяет проверить целостность и источник; она **не шифрует** содержимое токена.
- Проверяются подпись, issuer, audience и срок действия. В этой реализации токен выдаётся на 1800 секунд. Секрет подписи не должен попадать в репозиторий.
- Пароли хранятся в виде производного хеша PBKDF2 с солью, а не открытым текстом. Соль различает одинаковые пароли, множество итераций усложняет перебор.
- Знайте коды: 200 — успех, 201 — создано, 204 — успех без тела, 400 — некорректный запрос, 401 — проблема аутентификации, 404 — ресурс не найден.
- Swagger UI помогает изучать контракт и отправлять запросы; само наличие документации не защищает API.

### 5. PostgreSQL в Neon

- Покажите ту же API-логику, добавьте премию в избранное, прочитайте список и удалите её. Для доказательства постоянного хранения можно проверить сохранение после перезапуска сервера.
- Сущности: пользователи, премии, лауреаты, связи пользователя с избранными премиями. Внешние ключи поддерживают целостность связей.
- Составной первичный ключ пары «пользователь + премия» не позволяет добавить одинаковую связь дважды. Это связь многие-ко-многим между пользователями и премиями.
- Подготовленный запрос передаёт значения параметрами, а не склеивает пользовательский ввод с SQL. Это предотвращает превращение значения в SQL-команду.
- TLS защищает канал; проверка сертификата удостоверяет сервер. Это другая задача, чем проверка JWT или хеширование пароля.
- Секрет находится в локальном `.env`; в Git идёт `.env.example`. `.gitignore` не удалит секрет из истории, если его уже когда-то закоммитили.
- Найдите `schema.sql`, `PostgresPrizeRepository.kt`, `Passwords.kt`, `Routes.kt` и `ServerTest.kt`. Начальный набор содержит 6 премий и 11 лауреатов за 2023 год.

### 6. Клиент собственного API

- Сначала запустите сервер задания 5, затем клиент. В эмуляторе адрес сервера — `http://10.0.2.2:8080`; вход `student` / `Student123!`.
- Почему не localhost? В Android Emulator localhost указывает на сам эмулятор. `10.0.2.2` — адрес доступа к хосту в этом эмуляторе. На физическом телефоне нужен доступный LAN-адрес компьютера.
- Сохраняется доменный контракт репозитория, меняется его реализация и источник данных. Поэтому основные экраны могут использовать прежние модели.
- Проследите весь путь: PostgreSQL → сервер → HTTP/JSON → репозиторий клиента → ViewModel → Compose.
- HTTP здесь разрешён для локальной учебной разработки; для публичного размещения соединение следует строить через HTTPS.

### 7. BLE и пульс

- Покажите разрешения, запуск и окончание сканирования. Полный показ требует датчика или второго устройства с симулятором BLE-периферии.
- BLE отличается от обычного Bluetooth подходом к энергоэкономному обмену. В этой работе телефон — central/GATT-клиент, датчик — peripheral/GATT-сервер.
- Сервис группирует характеристики. Heart Rate Service имеет UUID 0x180D, Heart Rate Measurement — 0x2A37. Подписка включает уведомления характеристики и запись в CCCD 0x2902.
- Первый байт измерения содержит флаги; младший бит задаёт 8- или 16-битное представление пульса. При 16 битах младший байт идёт первым. Пример: флаг 1 и байты 0x2C, 0x01 дают 300.
- Почему важны проверки длины? Неполный пакет нельзя читать за границами массива. Четыре модульных теста проверяют форматы и некорректный пакет.
- Честный ответ о результате: интерфейс и парсер проверены, физическое соединение и реальный поток пульса без периферии не проверялись. Пустой список на эмуляторе сам по себе не доказывает ошибку кода.
