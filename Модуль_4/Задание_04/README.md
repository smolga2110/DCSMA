# Модуль 4. Практическая работа 4

Социальная лента с параллельной загрузкой данных

## Цель

Организовать независимую загрузку аватаров и комментариев к постам и показать состояние каждой карточки.

## Реализация

Лента содержит десять постов и отдельный JSON-файл комментариев. Для каждого поста запускаются две async-задачи внутри supervisorScope. Чтение файлов вынесено в Dispatchers.IO, а сетевое ожидание имитируется delay. Карточки переходят из Loading в Ready по мере готовности. Переключатель сбоев позволяет проверить состояния Error и замену отсутствующего аватара.

## Запуск

Требования: JDK 21, Android Studio, Android SDK Platform 35 и Build Tools 35. Откройте **эту папку** как отдельный проект Android Studio, дождитесь синхронизации и запустите конфигурацию app. Минимальная версия устройства — Android 8.0 (API 26). SDK задаётся через Android Studio, `ANDROID_HOME` или локальный `local.properties`.

Сборка из терминала: `./gradlew :app:assembleDebug` (Windows: `.\gradlew.bat :app:assembleDebug`). Готовый APK лежит в `apk/`; установка: `adb install -r apk/m4t04-debug.apk`.

На Windows при пути с кириллицей используйте `.\verify.ps1` (сборка) или `.\verify.ps1 run` (JVM). Сценарий обходит проблему путей Gradle test worker, размещая сборку в `%TEMP%/MobilePracticeBuild`. Произвольные задачи можно передать аргументами: `.\verify.ps1 TASK`. Путь можно переопределить переменной `PRACTICE_BUILD_DIR` на каталог с ASCII-именем. Для Android вместо TASK укажите `:app:testDebugUnitTest`, если в проекте есть тесты.

## Проверка

При штатном запуске карточки отобразили заголовок, текст и два комментария. Кнопка «Обновить» отменяет общий Job и все дочерние загрузки перед созданием нового набора задач. Ошибка одного поста не останавливает формирование остальных карточек.

Посты и комментарии учебные. Флажок ошибки позволяет проверить отказ загрузки; повторное обновление отменяет предыдущую загрузку.

## Файлы

`app/src/main` — код, ресурсы и манифест; `apk` — проверенная отладочная сборка.

`screenshots` содержит снимки реально запущенного приложения, если у работы есть интерфейс; `verification` — протоколы при наличии. Групповой отчёт находится в общей папке `Отчеты`. Каждый проект имеет собственный Gradle Wrapper и может публиковаться отдельно.
