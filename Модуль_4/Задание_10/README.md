# Модуль 4. Практическая работа 10

Определение адреса по текущим координатам

## Цель

Получить координаты через FusedLocationProviderClient и выполнить обратное геокодирование.

## Реализация

При нажатии кнопки проверяются разрешения ACCESS_COARSE_LOCATION и ACCESS_FINE_LOCATION. Запрос getCurrentLocation выполняется с ограничением 20 секунд. CancellationTokenSource отменяет запрос при завершении области ожидания. Координаты преобразуются в адрес через Geocoder в Dispatchers.IO. Экран показывает индикатор, адрес и значения широты и долготы.

## Запуск

Требования: JDK 21, Android Studio, Android SDK Platform 35 и Build Tools 35. Откройте **эту папку** как отдельный проект Android Studio, дождитесь синхронизации и запустите конфигурацию app. Минимальная версия устройства — Android 8.0 (API 26). SDK задаётся через Android Studio, `ANDROID_HOME` или локальный `local.properties`.

Сборка из терминала: `./gradlew :app:assembleDebug` (Windows: `.\gradlew.bat :app:assembleDebug`). Готовый APK лежит в `apk/`; установка: `adb install -r apk/m4t10-debug.apk`.

На Windows при пути с кириллицей используйте `.\verify.ps1` (сборка) или `.\verify.ps1 run` (JVM). Сценарий обходит проблему путей Gradle test worker, размещая сборку в `%TEMP%/MobilePracticeBuild`. Произвольные задачи можно передать аргументами: `.\verify.ps1 TASK`. Путь можно переопределить переменной `PRACTICE_BUILD_DIR` на каталог с ASCII-именем. Для Android вместо TASK укажите `:app:testDebugUnitTest`, если в проекте есть тесты.

## Проверка

Проверка выполняется на эмуляторе с заданной тестовой геопозицией. Предусмотрены отказ в разрешении, недоступность координат, таймаут и отсутствие адреса. Полученные координаты сохраняются для отображения даже тогда, когда сервис геокодирования не возвращает адрес.

Разрешите геолокацию. Для эмулятора задайте Location в Extended Controls. Проверка проводилась с координатами Москвы; обратное геокодирование требует сети.
