# Модуль 4. Практическая работа 1

Параллельная загрузка нескольких источников данных

## Цель

Освоить параллельный запуск независимых операций и получение их результатов без последовательного ожидания каждого источника.

## Реализация

В консольной программе созданы три асинхронные задачи: получение пользователей, статистики продаж и погоды. Задержки составляют 1800, 1200 и 2500 мс. Задачи запускаются внутри supervisorScope; результат каждого async представлен объектом Result. Вывод выполняется после завершения всех await. Исключение отмены передаётся выше, а ошибка отдельного источника преобразуется в понятное сообщение.

## Запуск

Требования: JDK 21 и интернет для первой загрузки зависимостей. Запуск из **этой папки**: `./gradlew run` (Windows: `.\gradlew.bat run`). Сборка: `./gradlew build`.

На Windows при пути с кириллицей используйте `.\verify.ps1` (сборка) или `.\verify.ps1 run` (JVM). Сценарий обходит проблему путей Gradle test worker, размещая сборку в `%TEMP%/MobilePracticeBuild`. Произвольные задачи можно передать аргументами: `.\verify.ps1 TASK`. Путь можно переопределить переменной `PRACTICE_BUILD_DIR` на каталог с ASCII-именем. Для Android вместо TASK укажите `:app:testDebugUnitTest`, если в проекте есть тесты.

## Проверка

В штатном запуске получены четыре имени, статистика по двум товарам и погода для трёх городов. Общее время составило 2,526 с. В режиме --fail источник пользователей завершился ошибкой, однако продажи и погода были выведены; приложение завершилось с кодом 0. Режим --random-failure позволяет воспроизвести случайный сбой.

Проверка ошибки: `./gradlew run --args="--fail"`. Для случайной ошибки используйте `--random-failure`.

## Файлы

`src/main` — код и ресурсы; `src/test` — тесты, если предусмотрены.

`screenshots` содержит снимки реально запущенного приложения, если у работы есть интерфейс; `verification` — протоколы при наличии. Групповой отчёт находится в общей папке `Отчеты`. Каждый проект имеет собственный Gradle Wrapper и может публиковаться отдельно.
