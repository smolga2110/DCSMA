# Модуль 4. Практическая работа 12

Генератор фактов на основе cold Flow

## Цель

Изучить холодный поток и сохранить показанный факт при пересоздании интерфейса.

## Реализация

FactViewModel содержит список из 15 фактов. Функция getRandomFact возвращает Flow<String>, который после задержки от 1500 до 3000 мс выдаёт один случайный элемент. Сбор начинается только по нажатию кнопки. Текущее значение и признак загрузки хранятся в StateFlow внутри ViewModel. AnimatedContent отвечает за смену текста карточки.

## Запуск

Требования: JDK 21, Android Studio, Android SDK Platform 35 и Build Tools 35. Откройте **эту папку** как отдельный проект Android Studio, дождитесь синхронизации и запустите конфигурацию app. Минимальная версия устройства — Android 8.0 (API 26). SDK задаётся через Android Studio, `ANDROID_HOME` или локальный `local.properties`.

Сборка из терминала: `./gradlew :app:assembleDebug` (Windows: `.\gradlew.bat :app:assembleDebug`). Готовый APK лежит в `apk/`; установка: `adb install -r apk/m4t12-debug.apk`.

На Windows при пути с кириллицей используйте `.\verify.ps1` (сборка) или `.\verify.ps1 run` (JVM). Сценарий обходит проблему путей Gradle test worker, размещая сборку в `%TEMP%/MobilePracticeBuild`. Произвольные задачи можно передать аргументами: `.\verify.ps1 TASK`. Путь можно переопределить переменной `PRACTICE_BUILD_DIR` на каталог с ASCII-именем. Для Android вместо TASK укажите `:app:testDebugUnitTest`, если в проекте есть тесты.

## Проверка

После нажатия «Новый факт!» отображён текст «Кошки используют усы для осязания». Во время ожидания кнопка недоступна. Повторная композиция не создаёт новый сбор потока; изменение конфигурации не требует новой генерации, поскольку результат принадлежит ViewModel.

Запросите факт, дождитесь ответа, поверните экран. На проверке факт сохранился после поворота.
